# Propose-After-Task Rule

For compromise-mode harnesses: the agent may not evolve the harness on its
own, but proposes after each task; the user decides; the default is not
adopting. Two forms — copy the one matching the sync family and adapt the
wording to the entrypoint's voice.

Entrypoint form:

````markdown
## Harness Proposals

After completing a task, if you noticed a harness gap — a missing rule, a
stale document, a procedure worth a skill — propose it in one or two
sentences with the evidence from this task. Do not apply it. The user
decides; when in doubt or unanswered, the proposal is not adopted. Never
edit the harness (this file, knowledge documents, skills, checks) except
on an explicit user decision.
````

Skill-family form — add this section to each sync skill built from the
sync-skill skeleton (or to the reclamation skill if that is the only
durable harness skill):

````markdown
## Proposing Beyond This Concern

If this run surfaced a harness gap outside this skill's concern, propose
it to the user in one or two sentences with the evidence — do not apply
it. The user decides; unanswered proposals are not adopted.
````
