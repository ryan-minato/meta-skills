# Docs Pages Contract

Read this before adding, editing, renaming, or removing anything under
`docs/`. Pages there are published verbatim as raw markdown to GitHub
Pages (`https://ryan-minato.github.io/meta-skills/`) together with a
CI-generated `llms.txt` index; agents in target projects fetch them on
demand during harness builds. Nothing in `docs/` is repository
documentation — the audience is a fetching agent, the language is
English, and READMEs never belong there (check E3 blocks them).

## Frontmatter

Every page opens with a YAML frontmatter block (the human-readable
mirror of check E1):

```yaml
---
title: Geospatial Analysis
description: Vector and raster stacks, CRS handling, and spatial engines.
tags: [data-science, geospatial]
---
```

- `title` — nonempty string, unique across `docs/` (E3): llms.txt links
  pages by title.
- `description` — nonempty one-liner; it is the page's entry in the
  llms.txt `## Pages` section, so write it for an agent deciding whether
  to fetch.
- `tags` — nonempty list of unique kebab-case slugs from the vocabulary
  below; each tag becomes an llms.txt section listing the page. The tag
  `pages` is reserved (it is the lead section's heading).

## Tag Vocabulary

Reuse before minting; a new tag needs a second page that would carry it.
Area axis (every page carries at least one):

`data-science` `machine-learning` `scientific-computing` `data-engineering`

Domain axis:

`storage` `tabular` `visualization` `geospatial` `graphs` `numerics`
`gpu` `simulation` `hpc` `distributed` `mlops` `inference` `llm`
`evaluation` `vision` `generative` `audio` `rl` `recsys` `time-series`
`probabilistic` `trustworthy` `training`

A page carries 2–5 tags. Check E1 enforces only the kebab shape; keeping
tags inside this vocabulary is on the author (an allowlist check is a
deferred mechanism in ARCHITECTURE.md).

## Page Format

H1 matching the title, a short "Fetch when…" paragraph telling the
agent which targets the page serves (end it with "No entry is a
recommendation."), a `## Tools` table, and optionally `## Gotchas` for
domain-specific traps:

```markdown
| Tool | One line | Docs |
|---|---|---|
| GeoPandas | dataframes with geometry columns | <https://geopandas.org/> |
| DuckDB | in-process analytical SQL | <https://duckdb.org/docs/> — llms.txt: <https://duckdb.org/llms.txt> |
```

- **Entry points only.** Record stable documentation roots — never
  versioned, deep, or `latest`-pinned URLs. When a site publishes an
  `llms.txt`, append it in the Docs cell after an em dash, as above.
- **Information, never recommendation.** Tables map tools to their
  docs; ranking or choosing between tools is the target user's decision
  and never appears on a page.
- **One row per tool, repository-wide.** A tool lives on its most
  specific page; other pages that need it point to it in prose ("pandas's
  time-series interface documents inside pandas — see the dataframes
  page"). Two deliberate ecosystem exceptions collapse into single
  pages/rows: everything under the Hugging Face docs root lives on
  `huggingface.md`, and Ray is one row (its libraries share one docs
  root).
- A dead URL discovered on a page is a bug: fix it in the same change,
  never leave a guessed substitute.

## Links

Local links may target sibling pages only — the published site serves
`docs/` alone, so a link into the rest of the repository 404s (check
E2). External links are absolute `https` URLs.

## Renaming And Removing

A page's filename is its public URL slug. Before renaming or removing
one, run `grep -r "<slug>.md" skills/ .agents/` and update every
reference in the same change — published skills may embed page URLs.

## Publishing

`llms.txt`, `index.html`, and the served copies are generated by
`scripts/build_docs.py` (locally: `just docs-build`, output in the
gitignored `_site/`) and deployed by the `pages` workflow on pushes to
main. Never commit build output; the pages themselves are the only
source of truth.
